# Graves Thinking Process — Canonical Stage Spec

Thomas advances only when stage questions are answered or explicitly overridden (override → pointed tone).

1. **problem_intake** — Parse the idea (including multimodal). Ask clarifying questions. Do not assume.
2. **existing_cheap_fix** — Is there an existing easy/cheap similar solution? Research buy/adopt vs build.
3. **good_problem** — Is this a good problem to solve? Who hurts, urgency, why now.
4. **risk_mvp_gate** — Risk potential → MVP vs go straight to production.
5. **solution_type** — Software / system change / physical / behavior / non-tech process; custom vs API integration of existing tools.
6. **laws_regs** — Applicable laws/regulations (healthcare, finance, etc.). Ask when unclear.
7. **cost_effective_path** — Most cost-effective path; DIY with user skills vs hire.
8. **whiteboard_decomposition** — Map solution on a whiteboard; break into process pieces → Process Whiteboard artifact.
9. **per_piece_tech** — Per piece: tech stack options; consolidation opportunities.
10. **architecture_stack** — Architecture and stack alternatives → chosen path.
11. **ops_cost** — Ongoing operational costs.
12. **final_design_map** — Final solution design map with major decisions → Solution Design Map artifact.
13. **build_approach** — How to build with max AI leverage, safely, IP-secure (plan only in v1).
14. **learn_retrospect** — Capture lessons for future runs.
