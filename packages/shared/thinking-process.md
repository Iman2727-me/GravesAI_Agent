# Graves Thinking Process — Canonical Stage Spec

Thomas advances when the current stage’s adaptive choice turns are done (or explicitly overridden → pointed tone).
Each stage: Thomas thinks → short verdict → at most one easy choice (up to 3 turns), then a brief stage summary.

1. **problem_intake** — Parse the idea. Infer what you can. One short choice that locks what a win looks like.
2. **existing_cheap_fix** — Judge buy/adopt vs build. Recommend a cheap existing fix when plausible; present cases.
3. **good_problem** — Judge if the idea is weak, unclear, or worth pursuing. Isaac accepts, reshapes, or kills.
4. **risk_mvp_gate** — Recommend MVP vs production-direct with a plain why; Isaac picks the case.
5. **solution_type** — Software / glue existing tools / process / hybrid; recommend and present cases.
6. **laws_regs** — Applicable laws/regulations. Ask one short choice when unclear; otherwise proceed.
7. **cost_effective_path** — Most cost-effective path; DIY+AI vs hire vs buy.
8. **whiteboard_decomposition** — Map solution on a whiteboard; break into process pieces → Process Whiteboard artifact.
9. **per_piece_tech** — Per piece: tech stack bias; consolidation opportunities.
10. **architecture_stack** — Architecture and stack alternatives → chosen path.
11. **ops_cost** — Ongoing operational costs.
12. **final_design_map** — Final solution design map with major decisions → Solution Design Map artifact.
13. **build_approach** — How to build with max AI leverage, safely, IP-secure (plan only in v1).
14. **learn_retrospect** — Capture lessons for future runs.
